# M3.2-B.2-P4B.1 — Production compatibility: ingest network, proxy trust, rollback

- **Status:** implemented and verified locally; **not deployed**. Production access during this
  work was read-only.
- **Baseline:** AFFILIO `445dcc2` (P1.1 + A1). Companion MeoScout change: `38aee9c`.
- **Scope (B1):** the `api` joins a dedicated, operator-created external network for the
  MeoScout bridge; every other service stays on the project's default network only; the API
  trusts `X-Forwarded-*` from an explicit proxy list instead of every peer. **Scope (B4):** a
  rollback sequence for migrations 0019/0020, verified against a disposable local database.

## 1. Network

`infrastructure/docker/synology/docker-compose.yml` now declares two networks:

| Network | Members | Notes |
| --- | --- | --- |
| `default` (`affilio_default`) | postgres, api, worker, publisher, exporter, web | unchanged; postgres and web are reachable only here |
| `affilio-ingest` → `${AFFILIO_INGEST_NETWORK}` | **api only** (+ the MeoScout bridge from its own project) | `external: true`; created once by the operator with `docker network create --internal <name>`; no `ports:` on the api, as before |

`docker compose config` (local, Compose v2.35) confirms: api on `[affilio-ingest, default]`,
all other services on `[default]`, only web publishes a port, and the file is refused when
`AFFILIO_INGEST_NETWORK` or `TRUSTED_PROXY_IPS` is unset.

`scripts/nas-deploy-remote.sh` preflight now fails when `AFFILIO_INGEST_NETWORK` is unset or
`TRUSTED_PROXY_IPS` is unset or contains `*`, and the deploy stops **before the backup and
before re-tagging the rollback images** when the ingest network does not exist on the daemon.

## 2. Proxy-header trust

| Before | After |
| --- | --- |
| `uvicorn … --forwarded-allow-ips "*"`: any peer that can reach port 8000 chooses the client address and scheme | `--forwarded-allow-ips "${TRUSTED_PROXY_IPS:-127.0.0.1}"` (`apps/api/docker-entrypoint.sh`) |
| `_client_ip` (login rate limit + audit) believed `X-Forwarded-For` whenever `TRUST_PROXY_HEADERS` was true | believed only when the direct peer is in `Settings.trusted_proxy_ips` (IPs or CIDR networks); `*` is refused outside development/test at startup, garbage is refused at startup |

Production value: the subnet of `affilio_default` (`docker network inspect affilio_default
-f '{{(index .IPAM.Config 0).Subnet}}'`), which contains the web proxy and excludes the
ingest network, so the bridge cannot spoof either layer. The web proxy keeps working: it
forwards `x-forwarded-for`, `x-forwarded-host` and `x-forwarded-proto` from inside that
subnet, exactly as today. Integration-key requests never used the client address (rate
limit keyed by key id), so nothing changes for them. `tests/test_trusted_proxies.py` covers
the parser, the production guard and `_client_ip` from trusted, untrusted and absent peers.

## 3. Rollback procedure for 0019/0020 (B4)

Migration review:

| Revision | Upgrade | Downgrade | Data at risk on downgrade |
| --- | --- | --- | --- |
| `0019_product_ingest` | tables `integration_api_keys`, `product_ingest_batches`, `product_ingest_items`; `products.ingest_batch_id` (FK, `SET NULL`) | drops the FK and column, both ingest tables and their indexes, then `integration_api_keys` | every integration key and every batch record; ingested **products stay** (source `meoscout`, `source_ref` = client_ref) |
| `0020_ingest_field_ownership` | `products.ingest_snapshot` (JSONB, nullable); `product_ingest_items.preserved_fields` (JSONB, default `[]`) | drops both columns | the per-field ownership record; after a later re-upgrade every existing product is treated as AFFILIO-owned (fill-only), the conservative default |

**The old image (`f8a0418`, head `0018_upload_root`) must never start against a 0019/0020
schema.** Its entrypoint runs `alembic upgrade head` on start and fails with
`Can't locate revision identified by '0020_ingest_field_ownership'`, leaving the api in a
restart loop. The schema must be downgraded by the **new** image first.

Sequence (all on the NAS, after a decision to roll back; nothing here runs automatically):

1. Stop MeoScout sending: `docker compose -p meoscout-bridge down` (outbox volume kept; every
   batch stays replayable). Note the integration key prefix shown in AFFILIO for the record.
2. Take a dump: `pnpm nas:deploy` already produced `backups/pre-deploy-<ts>.dump` before the
   migration; take a fresh one too (`scripts/db-backup.sh`) so ingest rows are not lost.
3. Downgrade with the **currently deployed (new) image**:
   `sudo docker compose -p affilio -f infrastructure/docker/synology/docker-compose.yml run --rm --no-deps api alembic downgrade 0018_upload_root`
   and confirm `select version_num from alembic_version` reads `0018_upload_root`.
4. Only then switch images: `pnpm nas:deploy rollback` (re-tags `:previous` as `:latest`,
   restarts; the old image's start-up `upgrade head` is a no-op at 0018).
5. Verify `/api/v1/system/info` (database ok) and `pnpm nas:status`.
6. If the downgrade itself fails: restore the pre-deploy dump with `scripts/db-restore.sh`
   (api and worker stopped), then step 4.

Drill (local, disposable database `affilio_rollback_drill`, dropped afterwards), using the
latest production dump (2026-11-04, revision 0018, 0 products, 1 organization):

| Step | Result |
| --- | --- |
| restore dump | `0018_upload_root`, no ingest tables, no extra product columns |
| `alembic upgrade head` | `0020_ingest_field_ownership`; 3 new tables; 2 new product columns |
| `alembic downgrade 0018_upload_root` (new scripts) | back to `0018_upload_root`; tables and columns gone; products and organizations unchanged |
| old scripts (`f8a0418`) against a 0020 schema | `FAILED: Can't locate revision identified by '0020_ingest_field_ownership'` — the case the sequence above avoids |
| `alembic upgrade head` again after the downgrade | `0020_ingest_field_ownership`, 2 migrations applied |

## 5. Required production configuration (operator, after approval)

1. `sudo docker network create --internal affilio-ingest` (or another name) — once.
2. In `/volume1/docker/affilio/infrastructure/docker/synology/.env`:
   `AFFILIO_INGEST_NETWORK=<that name>` and
   `TRUSTED_PROXY_IPS=<affilio_default subnet>` (never `*`).
3. `pnpm nas:sync` from a clean tree, `pnpm nas:deploy check`, then `pnpm nas:deploy deploy`
   with its own approval: it migrates to 0020 and recreates the api on both networks.
