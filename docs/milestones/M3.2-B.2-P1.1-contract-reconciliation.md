## 2. Replay safety (task 2)

**Approach chosen: preserve the exact original request.** AFFILIO's fingerprint is SHA-256
over `on_conflict` + `items` as sent (parsed JSON, sorted keys); `sent_at` and `source` are
excluded. The MeoScout relay must persist the serialized payload per `batch_id` and resend it
unchanged on retry (a new `sent_at` is fine). Canonicalizing on both sides was rejected: it
would need a byte-identical canonical form in TypeScript and Python and a shared spec for
every future field, while the exact-request rule needs nothing from AFFILIO beyond what P1
already does.

Verified: a new `sent_at`, `sent_at: null`, a new `source.build`, reordered keys and
re-indented JSON all replay; changed notes, evidence, price, a dropped item or a different
`on_conflict` under the same id are 409 `batch_mismatch` and write nothing; a failed batch
retried with a new `sent_at` re-runs; item-level retry after a partial batch creates only
the missing product; concurrent submissions of the golden batch create 3 products and 1 batch.

**Cross-repository gap (MeoScout, not fixed here):** MeoScout's `batch_id` hashes only the
item keys (identity + affiliate URL, `batchIdFor` / `itemKeyFor`), not the item content. A
rebuilt batch after a price, score, note or approval-time change gets the **same** id with
different content → `batch_mismatch`. MeoScout also classifies every 409 as retryable
(`applyIngestOutcome`), so it would retry a mismatch that can never succeed. See F1/F2.

## 3. Data ownership (task 3)

Rule (ADR 0014): ingest refreshes a research field only while the stored value is the one
ingest last wrote (`products.ingest_snapshot`); empty fields are filled; anything else is
kept and reported in `preserved_fields` (not a conflict). Products created by an editor, the
CSV import or before migration 0020 are fill-only. `affiliate_url` stays a kept conflict under
`on_conflict=keep`; identity is enrich-only; status, status history, procurement, production,
media links, affiliate links and publishing are never written (verified by a whole-database
snapshot of every table ingest must not write, around a conflicting batch).

## 4. Identity safety (task 4)

`platform_product_id` must be `<shopId>_<itemId>`; `product_url` must be on shopee.vn; ids the
URL states must match (→ `rejected` / `identity_mismatch`). A URL stating both ids supplies the
id; a manual product known only by such a URL is matched and its id enriched; a product that
shares only the item id (bare-id CSV row, `itemid`-only URL either way) is a
`conflict` / `identity_ambiguous` and nothing is written. Duplicates within a batch, across
URL spellings and across concurrent batches are covered by tests.

## 5. Security (task 5)

Unchanged: scoped key authentication, route allow-list, `products:ingest` scope, rate limit,
body cap, `on_conflict` default `keep`. No secret reaches MeoScout's extension (AFFILIO never
returns one from ingest); `ingest_snapshot` is never serialized.

## 6. MeoScout follow-ups (documented, not implemented — MeoScout changes need approval)

| # | Severity | Finding | Proposed MeoScout change |
| --- | --- | --- | --- |
| F1 | **blocking for P2** | `batch_id` covers identity + affiliate URL only; a rebuilt batch with changed content reuses the id → `batch_mismatch` | Either derive `batch_id` from the full canonical items (excluding `sent_at`) or, with the chosen exact-request approach, persist the payload per `batch_id` in the relay/`affilioDeliveries` and never rebuild under an existing id; a deliberate resend of changed data must get a new id |
| F2 | **blocking for P2** | `applyIngestOutcome` treats any 409 as retryable | Branch on `error.code`: `batch_in_progress` retryable, `batch_mismatch` final (`retryable: false`, "rebuild as a new batch") |
| F3 | medium | `.slice(0, 255)` on name / seller and `.slice(0, 20000)` on notes cut UTF-16 units and can leave a lone surrogate; `JSON.stringify` emits `\ud83d`, which AFFILIO's JSON parser refuses → **whole batch 422** (verified) | Truncate by code points (`Array.from(s).slice(0, n).join('')`) |
| F4 | low | `evidence` is unbounded (`search_query`, source refs); AFFILIO rejects items whose evidence exceeds 8 KiB | Cap `search_query` / refs, or measure evidence and drop optional keys before sending |
| F5 | low | Golden fixture pins `version: 2.0.0`; AFFILIO now refuses `2.1+` | Bump the minor only together with an AFFILIO release that accepts it |
| F6 | info | `AffilioIngestItemResult` lacks `preserved_fields` / `conflicts` | Add both (optional) so the panel can show "AFFILIO kept its own name" |
| F7 | info | `image_url` is the `_tn` thumbnail | Send the full-size image URL when available |
| F8 | info | `identity_mismatch` and `identity_ambiguous` are new codes | Show them as operator actions (`REJECTED` / `CONFLICT` mapping already fits) |
